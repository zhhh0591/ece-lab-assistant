# 2026-10-01

I built the ranging test for the MaUWB_DW3000 boards, working from Makerfabs'
UWB AT command manual (v1.1.2).

bridge.ino is new firmware for the ESP32-WROVER-B. It passes every line between
USB and the STM32, so the Mac sends the AT commands itself. All ten boards run
the same firmware, and whether a board is the anchor or a tag is set by command,
not compiled in.

ranging.py runs the test. It checks the board's MAC against its self-test
record, sets it up as a tag, and collects distances to a fixed anchor board for
15 seconds. It passes with at least 10 readings. The offset from the
tape-measured distance is recorded for calibration, not judged.

Before using real boards, I tested it against a simulated board in 7 cases:

1. Setting up the anchor board. Its settings read back correctly.
2. A normal board. It passes.
3. Older firmware, which formats its output differently. It passes.
4. The anchor switched off. It fails, as it should.
5. A re-run with the anchor on. It passes and clears the failure.
6. The wrong board on the port. It stops.
7. A board still running the self-test. It stops.

I also fixed a crash in analyze.py. It reads all the test results and groups
failed boards by the first check they failed, so I can see when several boards
fail the same way. It expected every check name to start with a step number,
like the five numbered steps in my general board test. The MaUWB self-test
names its checks instead, such as PSRAM and STM32AT, so analyze.py crashed as
soon as one of these boards failed. Now it uses the name when there is no
number. I checked that both kinds of name work.

and run the first real ranging test.
